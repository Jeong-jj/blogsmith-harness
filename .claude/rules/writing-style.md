# 문서 작성 규칙

이 레포의 모든 마크다운(README, ADR, SKILL.md, 가이드)과
커밋 메시지, PR 본문에 적용한다.
목표는 사람이 쓴 것처럼 읽히는 문서다.

## 종결

문서 종류에 따라 다르다. 한 문서 안에서 두 계열을 섞지 않는다.

| 대상 | 종결 |
|---|---|
| 커밋 메시지, PR 본문, ADR, CLAUDE.md, SKILL.md | 평서형과 명사형 |
| README, 사용자 가이드, 템플릿 안내문 | 존댓말 |

내부 문서에 구어체 존댓말을 쓰지 않는다.

```
넣었습니다        →  넣음
나와야 합니다      →  나와야 한다
네 줄만 받습니다   →  네 줄만 받는다
확인 못 했습니다   →  확인하지 못함 / 미확인
필요합니다        →  필요하다 / 필요
```

### 명사형의 범위

`-함`, `-음`으로 한정하지 않는다.

| 형태 | 예 |
|---|---|
| 용언의 명사형 `-음` `-함` `-됨` `-임` | 넣음, 확인함, 제외됨, 대상임 |
| 한자어 명사 | 미확인, 불가, 보류, 완료, 필요, 제외 |
| 체언 + 없음/있음 | 충돌 없음, 근거 있음 |
| 부정 | 쓰지 않음, 확인하지 못함 |

한자어 명사가 가장 짧다. `확인하지 못함`보다 `미확인`이 낫다.

### 섞는 기준

평서형과 명사형을 섞어 리듬을 만든다. 한쪽으로만 통일하면 딱딱해진다.

근거를 풀어 쓰는 문장은 평서형으로 쓴다.
상태나 결론을 끊을 때 명사형을 쓴다. 표와 목록 항목에도 명사형이 맞는다.

명사형만 이어 붙이면 전보문처럼 읽힌다. 문단 전체를 명사형으로 채우지 않는다.

아래 금지 항목의 `문장 중간의 명사화`와 헷갈리지 않는다.
그쪽은 문장 안에서 동사를 명사구로 뭉개는 번역투를 말한다.
여기는 문장을 끝맺는 방식이다. 서로 다른 얘기다.

## 금지

| 대상 | 대신 |
|---|---|
| em dash `—` | 쉼표, 콜론, 괄호, 또는 문장을 끊는다 |
| 번역투: `~에 대한`, `~에 있어서`, `~을 통해`, `~로 인해` | `~의`, `~에서`, `~로`, `~때문에` |
| `~라고 할 수 있습니다`, `~하는 것이 중요합니다` | 그냥 단정한다 |
| 문장 중간의 명사화: `이해를 높이는 것`, `활용을 통한` | 동사로: `이해한다`, `활용해서` |
| 피동: `~되어집니다`, `~라고 여겨집니다` | 능동으로 |
| 과장 형용사: 놀라운, 강력한, 혁신적인, 획기적인 | 뺀다. 근거 수치로 대체 |
| 메타 화법: `이 글에서는 ~를 살펴보겠습니다` | 본론부터 쓴다 |
| 마무리 상투구: `결론적으로`, `정리하자면` | 마지막 문단이면 안 써도 안다 |
| 이모지 소제목 | 텍스트 소제목 |

## 리듬

- 문장 길이를 섞는다. 긴 문장 뒤에 짧은 문장.
- 항목 수를 3개로 맞추지 않는다. 2개면 2개, 5개면 5개.
- 문단마다 요약 문장을 붙이지 않는다.
- 볼드는 한 화면에 두세 개까지. 전부 강조하면 아무것도 강조되지 않는다.

## 넣을 것

- 구체적인 수치와 고유명사. `상당히 빠르다`가 아니라 `200줄`
- 판단의 근거. 무엇을 포기했는지까지
- 실패하거나 막힌 지점. 잘 된 것만 쓰면 신뢰가 떨어진다

## 검사법

쓰고 나서 소리 내어 읽는다. 입에 안 붙는 문장이 번역투다.
