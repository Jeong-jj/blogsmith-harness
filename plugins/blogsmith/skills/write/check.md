# 검사 절차

`write` 8단계의 상세다. 셋을 차례로 거친다.

```
1  audit.py 를 돌린다          기계가 재는 것
2  읽고 판단할 여섯 항목         기계가 못 재는 것
3  source-checker 로 소스 대조   쓴 쪽이 판정할 수 없는 것
```

**순서를 바꾸지 않는다.** 3번이 1번보다 앞서면 `audit.py` 수정이 넣은 서술을 아무도 안 본다.
2번이 1번보다 앞서면 고치고 나서 또 판단해야 한다.

## 왜 여기에 있나

`SKILL.md` 본문은 500줄 미만이고 이 절차를 다 담으면 넘친다.

**목록은 `SKILL.md` 에 남겼다.** 지식 스킬에만 두었을 때 `write` 가 안 불러서
`review.md` 에 답이 비었다. 목록까지 옮기면 같은 일이 되풀이된다. **여기 있는 것은 각 항목에 무엇을 적는지와 그 근거다.**

`SKILL.md` 본문은 세션 시작 시점으로 고정되고 이 파일은 실행 시점에 디스크에서 읽힌다.
그래서 고치면 재시작 없이 반영된다. 반대로 **절차가 읽으라고 안 하면 안 읽고 지나간다.**

## 1. `audit.py`

**명령은 `SKILL.md` 8단계에 있다.** 여기 옮겨 적지 않는다.
스킬 경로가 치환되는 것은 `SKILL.md` 본문이고 이 파일은 그대로 읽힌다.
옮겨 적으면 안 풀린 자리 표시가 든 명령을 그대로 돌리게 된다.

검토 항목이 나오면 고치고 다시 돌린다. **최대 3회다.**

3회를 넘으면 대개 규칙끼리 충돌하는 상황이고 기계가 못 푼다.
남은 항목을 `review.md` 에 적고 **왜 못 고쳤는지**를 함께 쓴다.
규칙 충돌인지, 소스가 없어서인지, 판단이 필요한지 구분돼야 한다.

**고칠 수 없는 것만 남았으면 3회를 채우지 않는다.**
남은 것이 오탐이거나 소스에 없는 값을 요구하는 것이면 더 돌려도 결과가 같다.
그 상태에서 횟수를 채우려 들면 **없는 숫자를 지어내게 된다.**
두 번째 원칙을 어기는 자리다. 멈추고 `review.md` 에 적는다.

한 번 돌리고 남은 것을 하나씩 갈라 본다.

| 남은 것 | 어떻게 |
|---|---|
| 오탐 | 고치지 않는다. 한글 고유명사가 든 단위가 자주 걸린다 |
| 소스에 값이 없다 | 고치지 않는다. `못 지킨 것` 에 `[소스 부족]` 으로 넘긴다 |
| 소스에 값이 있다 | 고친다. 이때만 다시 돌린다 |

셋째가 하나도 없으면 다시 돌릴 이유가 없다.

**`audit.py` 와 문체 문서가 충돌하면 문체 문서를 따른다.**
`audit.py` 는 일반 규칙이고 문체 문서는 그 사람 개별 규칙이다.
이 경우 `audit.py` 결과는 경고로만 적는다.

**`audit.py` 절에는 통과 여부와 회수만 남긴다.** 잔여 항목은 `못 지킨 것` 에 모은다.
건수가 상태를 가리키게 하려는 것이고 `outputs.md` 가 정한 규격이다.

## 2. 읽고 판단할 여섯 항목

`natural-voice` 의 `에이전트가 읽고 판단할 것` 이다. 목록은 `SKILL.md` 에 있다.

**통과라고만 적지 않는다. 무엇을 보고 그렇게 판단했는지 한 줄씩 쓴다.**
답을 적어야 실제로 보게 되고, 사용자가 `review.md` 만 열어도 검사 범위를 안다.

| 항목 | 무엇을 적나 |
|---|---|
| 1 소리 내어 읽기 | 걸린 문장. 없으면 `걸리는 곳 없음` |
| 2 형용사 지워보기 | 어느 형용사를 무엇으로 바꿨는지 |
| 3 첫 문단의 숫자와 고유명사 | 실제로 있는 값을 적는다 |
| 4 견해와 단점 | 어느 문장이 그것인지 |
| 5 문단마다 요약 문장 | 있으면 어디인지 |
| 6 경험 서술의 근거 | `source-checker` 의 건수. 3번 절 참조 |

**3번을 띄우기 전에 1~5번 답을 대화에 먼저 낸다.** 여섯째는 3번이 끝나야 나온다.
`review.md` 는 9단계에서 생기므로 여기서 안 내면 건너뛰어도 드러나지 않는다.
개발 테스트에서 실제로 3번 뒤로 밀렸다. 9단계에서는 이 답을 옮겨 적는다.
3번에서 본문을 고쳐 답이 낡았으면 그 줄만 고친다.

**세 번째 항목이 특히 자주 샌다.**
`예전에 이슈였던 게 생각나서 찾아갔다` 처럼 무엇을 가리키는지 안 밝힌 도입이
`audit.py` 의 구체성 검사를 통과한다. 짧은 덩어리는 검사 대상에서 빠지기 때문이다.

**이 판단에서 본문을 고쳤으면 `audit.py` 를 확인용으로 한 번 돌린다.** 3번으로 넘어가기 전이다.
고친 본문의 결과를 모르면 `audit.py` 절에 적을 숫자가 낡는다.
3회 상한에는 안 센다. 되살아난 항목의 처리는 [source-check.md](source-check.md) 와 같다.

**`문체 재현` 절에는 지킨 것만 체크로 남긴다.** 미달 항목은 `못 지킨 것` 에 모은다.
1번 절의 잔여와 같은 처리다.

## 3. 소스 대조

여섯째 항목만 `source-checker` 에 맡긴다. `audit.py` 를 끝낸 뒤 띄운다.

절차는 [source-check.md](source-check.md) 에 있다. **그쪽을 읽고 한다.**
넘기는 것, 넘기지 않는 것, 고치는 법 둘, 고친 뒤 확인, `review.md` 에 적는 법이 거기 있다.

## 셋이 끝나면

답을 모아 9단계에서 `review.md` 를 쓴다. 절은 다섯이고,
`[읽기]` 로 연 사진이 있으면 `사진에서 읽은 값` 이 붙어 여섯이다. 형식은 [outputs.md](outputs.md) 에 있다.

```
audit.py            통과 여부와 회수
검색 노출 체크         플랫폼에 맞는 체크리스트
스크립트로 안 되는 검사   여섯 줄.  여섯째는 source-checker 의 건수
문체 재현             지킨 것만
못 지킨 것            못 지킨 것 전부가 여기 모인다
사진에서 읽은 값        [읽기] 사진이 있을 때만
```

**절을 임의로 더하지 않는다.** 실행마다 구성이 달라지면 두 판을 나란히 못 본다.
