# 산출물 형식

`output/<글감 폴더>/` 에 네 파일이 항상 나온다.

```
article.md    본문
photos.md     사진 순서, 위치, 캡션
meta.md       제목 후보, 태그, 메타 디스크립션, 발행 전 확인
review.md     audit 결과, 검색 노출 체크, 못 지킨 것
```

`meta.md` 는 발행할 때 보고 `review.md` 는 발행 전에 한 번 본다. 역할이 다르므로 나눈다.

같은 글감을 다시 써서 기존 것을 남기기로 했으면 `article.v1.md` 처럼 번호를 붙인다.
비어 있는 가장 작은 수를 쓴다. `v1` 이 있으면 `v2` 다.
`write` 는 `sources/` 만 읽으므로 이 파일들을 소스로 오해하지 않는다.

```markdown
source: 2026-08-03 성수동 카페
style: casual-review
platform: naver
created: 2026-08-13
---

# 성수동 코너스톤, 2층 창가가 정답이다

토요일 오후 2시에 갔다가
20분 기다렸다.

밖에 그늘이 없어서 좀 힘들었음.

![간판이 작아서 지나치기 쉽다](01_외관_간판작음.jpg)

## 2층 창가 자리를 노려라

2층 창가가 비어 있어서 앉았는데

오후 3시쯤 빛이 들어오는데 사진 찍기 좋다.
```

frontmatter 에 무엇으로 썼는지 남긴다. 나중에 결과가 나쁘면 어느 문체였는지 추적할 수 있다.

### 컴포넌트가 아니라 역할대로 적는다

| 역할 | 표기 |
|---|---|
| 글 제목 | `#` |
| 대제목 | `##` |
| 소제목 | `###` |
| 진짜 인용 | `>` |
| 구분선 | `---` |
| 굵게 | `**` |

**대제목을 인용 블록으로 쓰는 문체라도 `##` 로 적는다.**
의미상 제목인 것을 `>` 로 표시하면 마크다운으로서 틀리고,
티스토리와 velog 에서 제목이 인용문 상자로 렌더된다.
네이버에서는 어느 기호든 텍스트로 남아 사용자가 지워야 하므로 얻는 것도 없다.

**문체가 제목을 한 단만 쓰면 `##` 로 적는다.** 표의 `소제목 → ###` 은
대제목과 소제목이 둘 다 있는 문체를 전제한 것이다.
한 단뿐인데 문체 문서가 그것을 `소제목` 이라 부른다고 `###` 을 쓰면
`#` 다음에 `###` 이 와서 단계를 건너뛴다.

```
문체 문서   소제목: 1단만 쓴다. 계층 없음
나쁨       # 제목 → ### 서가        단계를 건너뛴다
좋음       # 제목 → ## 서가
```

`google-seo` 와 `geo-aeo` 가 소제목 구조를 읽는다. 건너뛴 단계는 그 구조를 흐린다.
**몇 단인지는 문체 문서의 관찰이 정한다.** 낱말이 정하지 않는다.
`대제목` `소제목` 은 그 블로거가 쓰는 말이라 문체마다 가리키는 것이 다르다.

어느 컴포넌트로 만들지는 `meta.md` 의 발행 전 확인이 안내한다.

### 문단 안 줄바꿈

위 예시는 `platform: naver` 라 개행만 있다. 플랫폼마다 표기가 갈린다.

```
naver                         tistory / velog / markdown

토요일 오후 2시에 갔다가       토요일 오후 2시에 갔다가··
20분 기다렸다.                 20분 기다렸다.
```

`··` 는 공백 두 칸이다. 마크다운은 개행 하나를 줄바꿈으로 보지 않아서
공백이 없으면 `토요일 오후 2시에 갔다가 20분 기다렸다.` 한 줄이 된다.

네이버는 붙여넣기에서 개행이 줄바꿈으로 살아남는다.
PC 웹 스마트에디터 ONE 과 모바일 앱 둘 다 확인했다. 그래서 공백을 넣지 않는다.

**백슬래시는 쓰지 않는다.** 한글 폰트에서 `₩` 로 렌더되어 본문에 그대로 남는다.

문단 안의 빈 줄은 플랫폼과 무관하게 빈 줄이다.
`2층 창가가 비어 있어서 앉았는데` 와 `여기가 제일 낫다.` 사이가 그 자리다.

**`naver` 로 만든 파일을 마크다운 미리보기로 열면 줄이 합쳐져 보인다.**
`article.md` 는 붙여넣기용 중간 산출물이고 렌더 대상이 아니다.
합쳐져 보이는 것과 붙여넣었을 때 나뉘는 것은 다르다.

## photos.md

```markdown
# 사진 배치

사진 4장. 에디터에 본문을 붙여넣고 표시된 자리에서 사진 버튼을 누르세요.
캡션은 그대로 복사해 쓰시면 됩니다.

| 순서 | 파일 | 위치 | 캡션 |
|---|---|---|---|
| 1 | `01_외관_간판작음.jpg` | 도입부 끝 | 간판이 작아서 지나치기 쉽다 |
| 2 | `02_2층창가.jpg` | "2층 창가 자리를 노려라" 첫 문단 뒤 | 2층 창가 자리 |
| 3 | `03_콜드브루와크로플.jpg` | "콜드브루는 산미가 강한 편" 첫 문단 뒤 | 콜드브루와 크로플 |
| 4 | `04_메뉴판.jpg` | "가격과 영업시간" 아래 | 없음 |

## 원본 위치

sources/2026-08-03 성수동 카페/

열어본 `.HEIC` 는 같은 폴더에 `.jpg` 로 변환해 두었습니다. 원본은 그대로 있습니다.

  04_메뉴판.HEIC  →  04_메뉴판.jpg

## 플랫폼 메모

**네이버**: 3번과 4번을 한 컴포넌트에 묶어 슬라이드로 넣어도 됩니다.
문체 문서에 슬라이드 묶음 습관이 있습니다.
```

본문에도 사진 자리가 표시되므로 표는 순서와 캡션을 한눈에 보는 용도다.
플랫폼 메모는 문체 문서에 관련 규칙이 있을 때만 쓴다.

**변환 줄은 실제로 바꾼 것이 있을 때만 쓴다.** 바꾼 파일을 하나씩 적는다.
안 연 사진은 바꾸지 않으므로 여기 나오지 않는다.
`sips` 가 없어 못 바꾼 것이 있으면 이 자리가 아니라 `review.md` 에 적는다.
산출물 넷의 역할이 달라서다. 여기는 사용자가 할 일을 적고 거기는 못 한 것을 적는다.

```markdown
30개까지 뽑았습니다. 이 중에서 골라 쓰세요.

## 메타 디스크립션

> 성수동 코너스톤 방문 후기. 2층 창가 자리가 가장 좋고 콜드브루는 산미가 강한 편이다.
> 주차는 안 되고 콘센트는 2층에만 있다. 콜드브루 6,500원.

## 본문 표시 읽는 법

article.md 에 붙은 기호입니다. 에디터에 붙여넣은 뒤 지우고 서식으로 바꾸세요.

  #    글 제목        ##   대제목        ###  소제목
  >    인용           ---  구분선        **   굵게
  ![캡션](파일명)  사진 자리

## 발행 전 확인

- 사진 4장을 에디터에서 업로드 (`photos.md` 순서대로)
- `##` 대제목 1개를 **인용 컴포넌트**로 지정
- 영업시간이 바뀌지 않았는지 확인 (2026년 8월 기준)
```

메타 디스크립션은 구글 색인이 되는 플랫폼에서만 쓴다.
네이버 전용이면 생략해도 된다.

**`본문 표시 읽는 법` 은 마크다운을 모르는 사용자를 위한 범례다.**
`article.md` 안에 넣으면 붙여넣을 때 딸려가므로 여기 둔다.

개수는 실제 문서에 있는 만큼 적는다. 위 예시는 대제목이 하나뿐이라 한 줄이다.
소제목과 구분선이 있으면 같은 형식으로 줄을 더한다.

**어느 컴포넌트로 지정할지는 문체 문서의 `플랫폼 종속 규칙` 이 정한다.**
대제목을 인용 컴포넌트로 만드는 것은 그 블로거의 습관이지 공통 규칙이 아니다.
다른 문체를 학습하면 소제목 컴포넌트일 수도 있다. 문체 문서를 보고 적는다.

```markdown
# 검수

```

1회차: 뻔한 수식 2건, 구체성 1건 → 수정

```
플랫폼: naver

- [x] 1인칭 경험 서술
- [x] 사실 정보가 전부 소스에 근거

## 스크립트로 안 되는 검사

`audit.py` 가 판정하지 못해 읽고 판단한 항목입니다. 한 줄씩 답을 적습니다.

- 소리 내어 읽기: 걸리는 곳 없음
- 형용사 지워보기: `아늑한` 을 지우니 뜻이 안 남아 `천장이 낮아 소리가 안 울린다` 로 바꿨습니다

- 견해와 단점: `작업하러 가기엔 애매하다`, 주차 불가를 적었습니다
- 문단마다 요약 문장: 없습니다
- 경험 서술의 근거: 웨이팅 20분과 콘센트 위치는 `notes.md` 에 있습니다
```

**절은 이 다섯이고 순서도 이대로다.** `[읽기]` 로 연 사진이 있으면
`사진에서 읽은 값` 이 마지막에 하나 더 붙는다. 그 밖의 절을 만들지 않는다.

절이 늘면 실행마다 구성이 달라져 두 판을 나란히 못 본다.
소스에 없어서 못 쓴 것은 절을 따로 만들지 말고
`못 지킨 것` 에 `[소스 부족]` 으로 넣는다. 같은 얘기가 두 곳에 갈린다.

**항목마다 사유를 대괄호에 붙인다.** 그냥 항목만 적으면 사용자가 판단을 못 한다.

| 사유 | 함께 쓸 것 |
|---|---|
| `[규칙 충돌]` | 어느 규칙과 부딪혔고 어느 쪽을 골랐는지 |
| `[소스 부족]` | 무엇이 없어서인지 |
| `[판단 필요]` | 사용자가 정해야 할 것 |
| `[플랫폼 제약]` | 그 플랫폼에 그 표현이 없어서인지 |

**대괄호에는 이 넷만 쓴다.** 무엇을 못 지켰는지는 대괄호 뒤 제목에 적는다.
`[사진]` `[분량]` `[관찰 초과]` 처럼 어긋난 자리를 대괄호에 넣으면
실행마다 이름이 달라져 두 판을 견줄 수가 없다.

**넷인 이유는 사용자가 할 일이 거기서 갈리기 때문이다.**
`[소스 부족]` 은 채워주면 되고 `[판단 필요]` 는 정해주면 된다.
`[규칙 충돌]` 과 `[플랫폼 제약]` 은 알고만 있으면 된다.
어긋난 자리를 대괄호에 넣으면 이 구분이 사라진다.

**마크다운 계열의 캡션이 여기 온다.** `플랫폼 제약` 에 해당한다.
`alt` 에는 넣었지만 화면에 보이는 캡션 문법이 없다.
에디터에서 사진을 올린 뒤 캡션란에 같은 문구를 넣으라고 알린다.

**HEIC 를 못 바꿔 안 연 사진도 여기 적는다.** `소스 부족` 에 해당한다.
파일명과 사용자가 그 사진에서 무엇을 기대했는지를 함께 쓰고,
자동 변환이 현재 버전에서 macOS 만 가능하다는 것을 한 줄 붙인다.

`audit.py` 가 3회 안에 통과하지 못했으면 남은 항목을 여기에 적는다.

```
[규칙 충돌] 편차 검사. 문장 길이 변동계수 0.31 (하한 0.35)
   문체 문서 규칙 3 "문장을 35자 안에서 끝낸다" 와 충돌합니다.
   문체 문서를 따랐습니다.

[소스 부족] 어휘 검사. 얼버무린 출처 1건 ['일반적으로']
   "일반적으로 웨이팅이 있다" 문장입니다.
   소스에 근거 수치가 없어 못 고쳤습니다. 실제 대기 시간을 아시면 넣어주세요.
```

**`audit.py` 의 검사 이름은 대괄호 뒤로 간다.** `편차` `어휘` 는 어긋난 자리이지 사유가 아니다.
같은 편차 하나라도 문체와 부딪혀 놔둔 것과 소스가 없어 못 고친 것은 사용자가 할 일이 다르다.

## 사진에서 읽은 값

`[읽기]` 로 연 사진이 있을 때만 붙인다. `review.md` 의 마지막 절이다.

읽은 값을 `notes.md` 와 맞춰보고 셋으로 갈라 적는다.

```markdown
## 사진에서 읽은 값

`05_가격표.jpeg` 를 열어 확인했습니다. `[읽기]` 가 붙은 한 장입니다.

`notes.md` 와 일치: 자몽차 7,500원, 아메리카노 5,000원, 밀크티 6,500원

`notes.md` 에 없던 값 중 쓴 것: 책 구매 시 음료 1,000원 할인.
`주문한 것` 소제목 마지막 문단에 넣었습니다.

`notes.md` 에 없던 값 중 안 쓴 것: 레몬차 6,500원, 초코쿠키 3,000원.
시키지 않은 메뉴라 넣지 않았습니다. 디저트가 있다는 것을 넣고 싶으시면 말씀해 주세요.
```

**안 쓴 값을 말없이 버리지 않는다.** 사용자는 그 사진을 골라 표시했는데
안에 무슨 값이 있었는지도 모른 채 끝난다. 적어두면 넣을지 사용자가 정한다.

**여기 적은 것은 `못 지킨 것` 에 또 적지 않는다.** 안 쓴 것에는 사유가 이미 붙어 있다.
