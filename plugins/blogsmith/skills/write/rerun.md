# 재실행

`write` 1단계에서 산출물이 이미 있을 때 무엇을 묻고 어떻게 동작하는지다.

```
output/2026-08-22 고든램지 스트릿버거/ 에 산출물이 있습니다 (2026-08-26 작성, platform naver).

1. 새로 씁니다. 기존 것을 덮어씁니다
2. 새로 쓰되 기존 것을 article.v1.md 처럼 남깁니다
3. 기존 것을 바탕으로 고칩니다. 무엇을 바꿀지 말씀해 주세요
```

**3번을 고르면 이전 산출물을 읽는다.** 문체와 소스가 같은데 새로 쓸 이유가 없다.
바꿀 자리만 손대므로 나머지가 흔들리지 않는다.

**1번과 2번을 고르면 이전 산출물을 읽지 않는다.**
읽으면 새로 쓴 것이 아니라 앞엣것을 다듬은 것이 된다.
품질을 재려고 다시 돌리는 경우가 여기다. 답안지를 보면 재는 의미가 없다.

`v` 번호는 비어 있는 가장 작은 수를 쓴다. `article.v1.md` 가 있으면 `v2` 다.

**묻지 않고 덮어쓰지 않는다.** `learn-style` 은 문체 문서가 있으면 덮어쓸지 확인한다.
같은 성격인데 한쪽에만 있었다.

### 플랫폼이 다르면 보기가 하나 더 붙는다

기존 산출물의 `platform` 이 이번에 쓸 플랫폼과 다르면 **나란히 두는 선택지를 낸다.**

```
output/2026-09-12 망원동 책방/ 에 산출물이 있습니다 (2026-08-28 작성, platform naver).
이번에는 markdown 으로 씁니다.

1. 나란히 둡니다. 기존 것은 article.naver.md 로 두고 새 것은 article.markdown.md 로 만듭니다
2. 기존 것을 바탕으로 고칩니다. 본문은 두고 플랫폼 자리만 바꿉니다
3. 새로 씁니다. 기존 것을 덮어씁니다
```

**한 글감을 두 플랫폼으로 내는 것은 흔한 일이다.** 크로스포스팅이 그렇다.
그런데 `v` 번호로는 그것을 못 담는다.

```
v 번호    시간 축.  같은 플랫폼을 다시 쓴 것
접미사     플랫폼 축.  같은 본문을 다른 곳에 낼 것
```

`article.v1.md` 만 봐서는 옛 판인지 다른 플랫폼인지 알 수 없다.

**나란히 둘 때는 양쪽 다 접미사를 붙인다.**

```
전    article.md          어느 플랫폼인지 파일명에 없다
후    article.naver.md    기존 것을 옮긴다
      article.markdown.md 새로 만든다
```

**접미사 없는 파일을 남기지 않는다.** 한쪽만 붙이면 안 붙은 쪽이 무엇인지 모른다.
넷 다 같이 옮긴다. `article` `meta` `photos` `review` 다.

플랫폼이 하나뿐인 글감은 접미사를 안 쓴다. 붙일 이유가 없다.

**1번과 2번은 이전 산출물을 읽는다.** 둘 다 본문을 잇는 것이 목적이다.
1번은 앞엣것을 남기고 2번은 그 자리에서 고친다.

### 이미 갈라져 있으면

접미사가 붙은 산출물이 있는 상태에서 또 다른 플랫폼으로 쓰는 경우다.
**옮길 것이 없으므로 새 접미사로 만들기만 한다.**

```
있는 것    article.naver.md   article.markdown.md
--platform tistory 로 실행

output/2026-09-12 망원동 책방/ 에 naver, markdown 판이 있습니다.
tistory 판을 만듭니다.

1. markdown 판을 바탕으로 고칩니다. 본문은 두고 플랫폼 자리만 바꿉니다
2. 새로 씁니다
```

**무엇을 바탕으로 삼을지 묻는다.** 판이 둘 이상이면 어느 것을 이을지 우리가 알 수 없다.
같은 계열이 있으면 그것을 먼저 낸다. `tistory` 는 `그 외` 계열이라 `markdown` 이 가깝다.

**같은 플랫폼이 이미 있으면 접미사가 아니라 `v` 번호다.**

```
있는 것    article.naver.md
--platform naver 로 다시 실행     →  article.naver.v1.md 로 남긴다
```

접미사가 먼저 오고 `v` 가 뒤에 붙는다. 플랫폼이 무엇인지가 먼저 보여야 한다.
