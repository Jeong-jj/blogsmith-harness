# 문체 문서 스키마

`styles/<이름>.md`의 형식이다. `style-analyst`가 이 형식으로 쓰고 `write`가 읽는다.

측정값과 명령형으로 채운다. 형용사로 채우면 `write`가 재현할 수 없다.

관찰한 편수를 항목마다 `(5/5)` 형태로 붙인다.
3편 이하에서만 나타난 것은 재현 규칙에 넣지 않고 관찰에만 남긴다.

해당 사항이 없으면 `없음`을 쓴다. 항목을 지우지 않는다.

---

```markdown
---
name: <스타일 이름>
sources: <읽은 글 수>
created: <YYYY-MM-DD>
---

# <스타일 이름>

<이 문체를 세 줄로. 처음 보는 사람이 감을 잡을 수 있게.>

## 화자와 독자

- 인칭:
- 독자 호칭:
- 말투:
- 거리감:

## 문장

- 종결어미:
- 평균 길이:
- 길이 편차:
- 줄바꿈 기준:

## 어휘

- 반복 표현:
- 입버릇과 감탄사:
- 이모지:
- 쓰지 않는 것:

## 구조

- 도입부:
- 소제목:
- 문단 길이:
- 마무리:

## 사진

- 글 대비 비율:
- 배치:
- 캡션:
- 언급 방식:

## 정보 밀도

- 사실 정보 위치:
- 표현 방식:

## 재현 규칙

<write 가 그대로 따를 명령. 관찰이 아니라 지시로 쓴다.>

1.
2.
3.

## 하지 말 것

<이 사람이 쓰지 않는 것. 여기가 비면 스타일이 뭉개진다.>

-
-

## 근거 발췌

<한 문장씩 서너 개. 문체의 증거일 뿐 재사용 금지.>

> 
> 

## 보류

<표본이 부족해 판단하지 못한 항목. 없으면 "없음".>
```

---

## 채운 예시

`재현 규칙`이 어느 정도로 구체적이어야 하는지 보여주는 예시다.

**나쁨**

```
1. 친근하게 쓴다
2. 사진을 적절히 배치한다
3. 정보를 잘 정리한다
```

무엇을 해야 할지 알 수 없다. `write`가 이 문장으로 재현할 수 있는 것이 없다.

**좋음**

```
1. 해요체로 쓴다. 합니다체를 섞지 않는다.
2. 문장을 40자 안에서 끊는다. 길어지면 두 문장으로 나눈다.
3. 소제목마다 문단 2개를 넘기지 않는다.
4. 사진은 소제목 바로 아래에 놓고, 사진을 설명하는 문장을 그 앞에 둔다.
5. 가격과 영업시간은 본문에 녹이지 말고 글 끝에 목록으로 모은다.
6. 이모지는 소제목에만, 하나씩만 쓴다.
```
