# 플랫폼별 자동 수집 방침

조사 시점 2026-08-09. `robots.txt`를 직접 확인한 결과다.

## blogsmith 의 원칙

**신분을 밝히고 받는다.** 브라우저인 척하지 않는다.

```
User-Agent: blogsmith/0.1 (+https://github.com/Jeong-jj/blogsmith-harness)
```

받아주면 쓰고, 막으면 물러난다. 우회하지 않는다.
막혔을 때는 사용자에게 대안을 안내하고 끝낸다.

## 현황

| 플랫폼 | 본문 수집 | robots.txt |
|---|---|---|
| velog.io | 가능 | `User-agent: *` 만 있고 제한 없음 |
| `*.tistory.com` | 가능 | 관리 페이지(`/manage` `/admin` `/search`)만 차단. 글 본문은 허용 |
| blog.naver.com | 가능 | ClaudeBot 등 AI 크롤러를 이름으로 차단. 아래 참고 |
| brunch.co.kr | 확인 필요 | ClaudeBot 등 AI 크롤러를 이름으로 차단 |

**현재 버전이 다루는 곳은 앞의 셋이다.** 브런치는 확인하지 않았고 추후 개발 예정이다.
본문 수집과 실패 판정을 셋에서만 재봤으므로 다른 곳은 둘 다 보장하지 않는다.

## 본문 영역을 잡는 이름

2026-08-27 에 세 플랫폼을 열어 쟀다.

| 플랫폼 | 본문 래퍼 |
|---|---|
| 네이버 | `se-main-container`. 구버전은 `id="postViewArea"` |
| 티스토리 | `<article>` |
| velog | 해시 클래스 `sc-...` 와 함께 붙는 `atom-one` |

**velog 는 래퍼 클래스가 빌드마다 새로 만들어진다.** `sc-eGRUor bzHCOc atom-one` 처럼
앞의 둘은 styled-components 가 만든 해시라 박아두면 다음 배포에 깨진다.
같은 요소에 붙는 `atom-one` 이 남는 이름이다. 세 편에서 확인했다.

못 찾으면 문서 전체를 넘기는데 그때 무엇이 섞이는지 쟀다.

```
velog 한 편   전 9묶음 10장   프로필 사진과 댓글 작성자 썸네일이 섞임
              후 5묶음  6장   본문의 실제 이미지와 일치
```

**67% 부풀어 있었다.** 네이버에서 컨테이너를 `(.*)` 로 잡아 사진이 세 배가 됐던 것과
같은 종류다. 소제목도 `H1` 7개에서 6개, `H2` 8개에서 6개로 줄었다.
관련글 목록과 내비게이션이 소제목으로 세어지고 있었다.

## 캡션 마크업

| 플랫폼 | 캡션 |
|---|---|
| 네이버 | `se-caption` |
| 티스토리 | `<figure class="imageblock">` 을 쓴다. 캡션은 표준 `<figcaption>` |
| velog | **없다.** 마크다운 `![alt](url)` 이 맨 `<img>` 로 렌더된다 |

둘 다 읽는다. 네이버 것을 먼저 보고 없으면 `<figcaption>` 을 본다.

**`<figcaption>` 은 HTML 표준이고 캡션 말고 다른 뜻이 없다.** 오탐이 안 나므로
플랫폼을 가리지 않고 본다. 없으면 아무 일도 안 일어난다.

**velog 에서 캡션 관찰이 0인 것은 결함이 아니다.** 플랫폼에 그 기능이 없다.

티스토리 실물로 확인했다. 이미지를 `<span data-url>` 로 감싸는 자체 구조를 쓰면서
캡션은 표준을 쓴다.

```html
<figure class="imageblock alignCenter" ...>
  <span data-url="...kakaocdn.net/..."><img .../></span>
  <figcaption>리액트 배너</figcaption>
</figure>
```

## 막히는 방식이 플랫폼마다 다르다

2026-08-27 에 열한 경우로 쟀다.

| | 응답 | 무엇이 잡나 |
|---|---|---|
| 네이버 비공개 | 200, 안내 페이지로 갈아치움 | `og:type` |
| 네이버 없는 글 | 404 | 상태 코드 |
| velog 비공개 | 404 또는 200 | 상태 코드 또는 `og:type` |
| velog 없는 글 | 404 또는 200 | 같음 |
| 티스토리 비공개 | 403 | 상태 코드 |
| 티스토리 보호글 | 200, `og:type=article` | 비밀번호 입력칸 |
| 티스토리 없는 글 | 404 | 상태 코드 |
| 블로그 메인 주소 | 200, `og:type=website` | `og:type` |

**velog 는 비공개와 없는 글을 구분해 주지 않는다.** 둘 다 같은 안내 페이지를 준다.
본문이 글자까지 같다. 비공개 글의 존재를 숨기는 것이 velog 의 의도로 보인다.
있다고 알려주면 주소를 바꿔가며 존재 여부를 캐낼 수 있다.

그리고 velog 는 같은 주소가 첫 요청에 404, 다음에 200 으로 온다. SSR 캐시 때문이다.
**실패로 잡히는 것은 같지만 사유 문구가 실행마다 달라질 수 있다.**

**티스토리 보호글이 제일 까다롭다.** 글 페이지 껍데기에 비밀번호 화면만 얹혀 오므로
`og:type` 이 `article` 그대로다. 본문에 비밀번호 입력칸이 있는지로 따로 본다.

## 네이버를 어떻게 볼 것인가

네이버 `robots.txt`에 이렇게 적혀 있다.

```
# BOT ACCESS FOR THE PURPOSES OF AI TRAINING AND
# RETRIEVAL-AUGMENTED GENERATION (RAG) IS STRICTLY PROHIBITED.
User-agent: ClaudeBot
Disallow: /
```

**blogsmith 는 여기서 지목된 대상이 아니라고 본다.** 근거는 셋이다.

ClaudeBot 은 Anthropic 이 학습과 검색 색인 목적으로 웹을 훑는 크롤러다.
blogsmith 는 사용자가 직접 고른 최대 6개 주소만 읽는다. 링크를 따라가지 않는다.

수집한 내용을 학습 데이터로 쓰지 않고 저장하지도 않는다.
추출하는 것은 문체 규칙이며 원문은 남기지 않는다.

실제 서버 동작으로도 확인했다. `User-Agent` 를 `ClaudeBot` 으로 밝히면 차단되지만,
`blogsmith` 로 밝히면 정상적으로 응답한다. 네이버가 막는 대상에 우리가 들어 있지 않다.

**네이버가 blogsmith 를 막기 시작하면 그때는 물러난다.** 우회하지 않는다.

## 법적 검토

`robots.txt` 위반 자체는 불법이 아니다. 법적 구속력이 없는 관행이다.

형사 쪽은 대법원이 정리했다. 공개 페이지 접근을 정보통신망 침입으로 보기 어렵다는 취지로
무죄가 확정됐다 (2022. 5. 12. 선고 2021도1533).

민사 책임이 인정된 사례는 있다. 다만 문제가 된 것은 아래 조건이 겹친 경우다.

- 경쟁 사업자의 데이터베이스를 통째로 복제
- 수집한 내용을 자사 서비스에 그대로 게재
- 대량 요청으로 서버에 부담

blogsmith 는 최대 6개 요청이고, 원문을 저장하지 않으며, 상업적 경쟁 관계가 없다.

## 새 플랫폼을 지원할 때

먼저 `robots.txt` 를 확인한다.

```bash
curl -s https://<도메인>/robots.txt
```

AI 크롤러를 이름으로 차단하는지, `User-agent: *` 에서 글 본문 경로를 막는지 본다.
그다음 `blogsmith` UA 로 실제 응답이 오는지 확인한다.

둘 중 하나라도 막히면 자동 수집을 넣지 않는다. 이 문서에 근거와 함께 기록한다.
