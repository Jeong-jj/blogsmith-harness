# 이 예시의 고정값

`examples/README.md` 의 회귀 절차를 이 예시에 적용할 때 쓰는 값이다.
공통 절차는 그쪽에 있고 여기는 이 예시에서만 맞는 숫자를 둔다.

`write` 는 매번 다르게 쓴다. **문장이 같기를 기대하면 통과할 수가 없다.**
아래 항목만 본다.

## 무엇으로 만들었나

```
문체      style/_raw/ 세 편으로 learn-style.  주소 없음, 붙여넣기만
          플랫폼은 물어서 naver 로 답했다
글감      sources/notes.md 와 사진 여섯 장
설정      imageMode: filename
산출      write 두 번. --platform naver 먼저, 그다음 --platform markdown
          첫 번째는 1단계에서 `새로 씁니다` 를 골랐다
          두 번째는 플랫폼이 달라 `나란히 둡니다` 를 골랐다
갱신      2026-11-24.  규격이 셋 바뀐 뒤 다시 돌린 판이다

작업공간에서는 `나란히 둡니다` 가 `article.naver.md` 와 `article.markdown.md` 로 가른다.
여기 `output/naver/` `output/markdown/` 은 그것을 보기 좋게 나눈 것이고
접미사를 떼어 뒀다. `naver.html` 만 이름에 플랫폼이 있어 그대로다.
```

**`--style example-style` 을 명시해야 한다.** 작업공간 `defaultStyle` 이 다른 값일 수 있다.

**원문이 두 곳에 있다.** 여기 `style/_raw/` 가 정본이고
`workspace/styles/_raw/example-style/` 은 실행용 사본이다.
돌리기 전에 여기서 그쪽으로 복사한다. 반대로 하지 않는다.

## 기계가 재는 것

에이전트 판단이 안 끼는 값들이다. 여기가 어긋나면 확실히 나빠진 것이다.

- [ ] `audit.py` 종료 코드 1. 남는 것은 구체성 한 건뿐이다 (아래 `알려진 오탐`)
- [ ] 산출물 넷이 두 플랫폼 모두 생성. `article.md` `meta.md` `photos.md` `review.md`
- [ ] `naver` 쪽에 `naver.html` 하나 더. `markdown` 쪽에는 없다
- [ ] `article.md` 의 이미지 참조 6개. 파일명이 `notes.md` 의 사진 목록과 일치
- [ ] `review.md` 의 절 여섯. `audit.py` `검색 노출 체크` `스크립트로 안 되는 검사`
      `문체 재현` `못 지킨 것` `사진에서 읽은 값`
- [ ] `article.md` 의 헤딩이 `#` 하나와 `##` 넷. `###` 이 없다
- [ ] `못 지킨 것` 의 대괄호가 `규칙 충돌` `소스 부족` `판단 필요` `플랫폼 제약` 넷 안이다
- [ ] `문체 재현` 절에 미체크 항목이 없다. 못 지킨 것은 아래 절에만 적는다

`naver.html` 은 `article.md` 에서 만드는 파생물이라 따로 재는 값이 있다.

- [ ] 묶음 마커 5개. `photos.md` 의 묶음 수와 같다. 사진 장수인 6개가 아니다
- [ ] `<h2>` 4개. 이 문체는 소제목 컴포넌트를 쓰므로 `<blockquote>` 가 아니다
- [ ] `<h1>` 0개. 글 제목은 에디터의 제목 칸에 따로 넣는다
- [ ] `<img>` 0개. 사진은 자리 표시 문단으로만 둔다

## 플랫폼이 가르는 것

두 판을 나란히 두었으므로 차이가 유지되는지 본다.

| | naver | markdown |
|---|---|---|
| `alt` | 6개 전부 비어 있다 | 6개 전부 채워져 있다 |
| 본문 | 602자 | 602자 |
| 못 지킨 것 | 6건 | 8건 |
| `naver.html` | 있다 | 없다 |

**`alt` 가 이 예시의 핵심 갈림이다.** 네이버는 사용자가 그 줄을 지우고 사진 버튼을 누르므로
채우면 지울 것만 는다. 마크다운 계열은 `google-seo` 가 요구한다.

**본문이 `alt` 를 빼면 한 글자도 다르지 않아야 한다.**

```bash
diff <(sed '1,/^---$/d;1,/^---$/d' output/naver/article.md     | sed 's/!\[[^]]*\]/![]/') \
     <(sed '1,/^---$/d;1,/^---$/d' output/markdown/article.md | sed 's/!\[[^]]*\]/![]/')
```

플랫폼만 바꾼 재실행이 본문을 통째로 다시 쓰면
`기존 것을 바탕으로 고칩니다` 가 동작하지 않은 것이다.

**`못 지킨 것` 의 공통 6건이 같아야 한다.** 사진 묶음 수, 소제목 뒤 사진, 사진 없는 문단,
출구 번호, 방문 날짜, 구체성 검사다. 여기가 갈리면 플랫폼이 아닌 것이 갈린 것이다.

## 문체 문서가 정하는 것

- [ ] 사진 묶음 5개. 1장 네 묶음과 2장 한 묶음
- [ ] 소제목 4개. 문장부호 없는 2~8자 구
- [ ] 본문 구분선 0개. frontmatter 의 `---` 둘은 세지 않는다

**미확인 셋이 산출물에 없어야 한다.**

- [ ] 캡션 0개
- [ ] 본문 구분선 0개
- [ ] 지도·링크 카드 0개

셋 다 문체 문서에서 `미확인` 이다. 학습 원문이 붙여넣기라 원래 썼는지 알 수 없다.
**있으면 문체 문서를 어긴 것이고, `0회` 로 적혀 있으면 미확인을 없는 것으로 뭉갠 것이다.**

## 늘면 나빠진 것

```
naver      못 지킨 것 6건
markdown   못 지킨 것 8건
```

공통 6건 위에 markdown 쪽만 둘이 더 붙는다.

```
markdown   [판단 필요] 기준 시점을 본문에 안 적음      geo-aeo
           [판단 필요] 저자 정보가 본문에 없음         google-seo 의 Who
```

**markdown 이 둘 많은 것은 3단계 지식 매핑 그대로다.**
`naver` 는 `naver-seo` 만 물리고 `그 외` 는 `google-seo` 와 `geo-aeo` 를 함께 문다.
이 둘이 사라지면 매핑이 안 걸린 것이다.

**`audit.py` 잔여를 `못 지킨 것` 에 센다.** PR #71 에서 규격으로 못 박았다.

전에는 `outputs.md` 가 `못 지킨 것` 에 적으라고 하는데 실행이 `audit.py` 절에 뒀다.
같은 글감을 두 번 돌려보니 두 판이 서로 다른 절에 넣었다.

```
2026-08-28 판    못 지킨 것 5건 + audit 절 2건   실제 항목 7개
2026-11-24 판    못 지킨 것 6건 + audit 절 0건   실제 항목 6개
```

**건수가 센 것을 못 가리켰다.** 항목이 하나 줄었는데 기준 숫자는 5에서 6으로 늘었다.

지금은 `audit.py` 절에 통과 여부와 회수만 남고 사유 대괄호가 붙는 것은 전부 아래 절에 모인다.
`문체 재현` 절도 같다. 지킨 것만 체크로 남긴다.
**그래서 `못 지킨 것` 건수가 그대로 상태를 가리킨다.**

**늘었으면 무언가 나빠진 것이고, 줄었으면 잡던 것을 못 잡게 됐을 수 있다.**
숫자만 보고 원인은 사람이 본다.

## 알려진 오탐

- `audit.py` 구체성 1건. 두 판 모두 같다. 8단위 중 6단위가 걸린다.
  `망원역` `열 평` `육 분` 같은 한글 고유명사와 한글 수사를 스크립트가 못 센다.
  문체 규칙 9 가 금액 외의 수를 한글로 쓰게 해서 생기는 충돌이다.
  **고쳐지면 오히려 확인이 필요하다.** 검사가 넓어진 것인지 글이 달라진 것인지 갈린다.

## 비교하지 않는 것

문장, 문단 수, 어떤 견해를 골랐는지, 소제목 문구.

`write` 는 매번 다르게 쓴다. 같기를 기대하면 통과할 수가 없다.

## 이 픽스처가 못 재는 것

**붙여넣기 경로의 손실은 여기서 안 잰다.** 원문에 `(사진: 메뉴판)` 같은
자리 표시를 사람이 적어 넣은 형태라, 아무것도 안 적힌 순수 복사본과 다르다.
그 손실은 `raw.md` 에 따로 재둔 값이 있다.

**캡션의 마크다운 대체도 여기서 안 된다.** 문체 문서가 캡션을 `미확인` 으로 두어
두 판 모두 캡션이 없다. `그 외에서는 alt 로` 는 다른 자리에서 봐야 한다.

**`naver.html` 의 변환 경로 절반은 안 밟힌다.** 이 문체가 인용구와 목록과 표를 안 쓴다.
`<h2>` 와 문단과 묶음 마커까지만 걸리고 `<blockquote>` `<hr>` `<ul>` `<table>` 은
두 번째 예시가 와야 걸린다.

**소스에 없는 서술을 거르는 것도 여기서 안 잰다.** 이 판을 만들 때 초안에 셋이 들어갔고
사람이 `notes.md` 와 대조해 걷어냈다. `audit.py` 는 소스를 안 읽어 못 본다.
