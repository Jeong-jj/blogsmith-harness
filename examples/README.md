# examples

실제로 만든 입력과 결과물을 남기는 곳입니다.

```
examples/
└── 001-<주제>/
    ├── style/
    │   ├── _raw/      문체 학습에 쓴 원문
    │   └── style.md   learn-style 이 만든 문체 문서
    ├── sources/       write 입력으로 쓴 사진과 메모
    ├── output/        플랫폼별 결과물
    └── expected.md    이 예시의 고정값
```

**문체 문서를 결과만 두지 않고 원문과 함께 둔다.** 문체 문서는 관찰에서 나오는 것이라
결과만 있으면 그 규칙이 어디서 왔는지 확인할 방법이 없다.
원문이 있으면 회귀에서 `learn-style` 도 돌려볼 수 있다.

두 가지 목적입니다.

- 처음 온 사람이 저장소를 클론하지 않고도 무엇이 나오는지 봅니다
- 스킬을 고칠 때마다 여기로 돌려서 결과가 나빠지지 않았는지 확인합니다

## 회귀를 어떻게 돌리나

```
1. style/_raw/ 를 workspace/styles/_raw/<이름>/ 으로 복사한다
2. learn-style 을 돌려 문체 문서를 다시 만든다
3. sources/ 를 workspace/sources/<글감>/ 으로 복사한다
4. write 를 플랫폼마다 돌린다
5. expected.md 의 항목을 하나씩 본다
```

**4번에서 두 번째 플랫폼을 돌리면 나란히 둘지 묻습니다.**
나란히 두면 `article.naver.md` 와 `article.markdown.md` 로 갈려 손으로 백업할 것이 없습니다.

**정본은 여기다.** 작업공간은 실행용 사본이고 반대 방향으로 복사하지 않는다.

**바이트 비교는 안 한다.** `write` 는 매번 다르게 쓴다.
같기를 기대하면 통과할 수가 없으므로 무엇을 보는지 예시마다 `expected.md` 에 적어둔다.

무엇을 볼지는 성격으로 나뉜다.

| 갈래 | 왜 |
|---|---|
| 기계가 재는 것 | 에이전트 판단이 안 낀다. 어긋나면 확실히 나빠진 것이다 |
| 플랫폼이 가르는 것 | 같은 본문에서 플랫폼만 바꿨을 때 갈리는 자리 |
| 문체 문서가 정하는 것 | 관찰에서 나온 값이라 소스가 같으면 같아야 한다 |
| 늘면 나빠진 것 | `못 지킨 것` 의 항목 수. 숫자만 보고 원인은 사람이 본다 |
| 알려진 오탐 | 고쳐졌으면 그것도 확인 대상이다 |
| 비교하지 않는 것 | 문장, 문단 수, 견해, 소제목 문구 |

**`review.md` 만 보고 통과로 치지 않는다.** 그것은 에이전트가 자기 일을 스스로 채점한 결과다.
밖에서 검증되는 것은 `기계가 재는 것` 뿐이고 나머지는 그 채점을 읽는 것이다.

`plugins/blogsmith/skills/init/template/`과 혼동하지 마세요.
그쪽은 `/blogsmith:init`이 사용자 디렉토리로 복사하는 빈 뼈대이고,
여기는 채워진 결과물입니다.
